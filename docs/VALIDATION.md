- Windows，Python 3.9.25。
- PyTorch 2.7.1+cu128，Torchvision 0.22.1+cu128，CUDA 可用。
- Torchreid 0.2.5，NumPy 2.0.2，OpenCV 4.13.0.92。

- 95 个 Python 文件通过语法解析，13 个 JSON 配置的字段与对应命令行入口一致。
- 配置引用的实验文件和 Markdown 相对链接均存在。

- 使用 `pip wheel --no-deps --no-build-isolation --no-index` 成功构建纯 Python wheel，标准 COCO 评估器导入通过。
- `byte_tracker.py`、`matching.py`、`reid_extractor.py`、`gmc.py` 和 `kalman_filter.py` 与原工作区源码的 SHA-256 相同。

## 三帧完整推理

在发布版目录中运行 `scripts/verify_release.py --runtime`，使用本地已有 YOLOX-x 和 OSNet-x1.0 权重。检测尺寸缩小为 640×640，仅用于检查链路；同时开启 ReID、长时恢复和 CMC。

| 帧 | 检测数 | 输出轨迹数 |
| --- | ---: | ---: |
| 1 | 27 | 15 |
| 2 | 24 | 15 |
| 3 | 23 | 15 |

检测模型加载无缺失键，三帧都产生有效轨迹，并生成了带 ID 的验证图片。推理调用来自发布版目录，没有使用工作区原版演示入口。

该验证检查代码、模型加载和基本推理流程，三帧没有覆盖自然发生的长时遮挡恢复事件，不作为跟踪精度或速度评估。

## 验证范围

本次没有在全新机器重新安装依赖，没有重训 ReID，也没有重新运行完整 MOT17/MOT20 测试集或上传官方评估服务器。CPU 配置通过静态字段检查，尚未执行完整 CPU 视频推理。

公开包采用标准 COCO 检测评估器，未重新核对其与历史快速 C++ 评估器的整集结果差异。完整实验复现需另外准备数据、权重和相同评估设置。
